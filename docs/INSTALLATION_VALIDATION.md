# 隔离安装验收

本地构建成功和直接启动EXE不能证明安装、升级或卸载通过。验收在专用的一次性Windows 10/11虚拟机中进行；更换宿主安装目录不能隔离相同的卸载注册表标识。

## 记录输入

- Windows版本、架构、WebView2版本、用户权限以及虚拟机干净快照。
- 基线包与候选包各自的源码提交、构建命令、文件名、SHA256。未提交构建需附源码指纹清单，不能只记main或0.1.0。
- 同一候选源码的普通CI、显式Shell专项、原生专项及安装包摘要；构建和专项通过状态分别记录。
- 使用[候选包留档工具](CANDIDATE_EVIDENCE.md)保留安装包、摘要、源码身份和实际检查记录；CI Artifact仅代表该运行的候选材料，不代替以下隔离安装验收。

## 验收顺序

1. 干净快照首次安装候选包，核对实际安装路径、快捷方式、卸载项与显示版本；通过快捷方式启动。
2. 在虚拟机内用合成目录完成选择、扫描、改动保留项、确认、回收与结果详情；确认保留副本完整，能从回收站恢复测试副本。
3. 还原干净快照，先安装记录过的旧包，再升级候选包。检查启动、版本与卸载项，单独记录同版本覆盖和跨版本升级，不能相互替代。
4. 通过系统已安装应用入口卸载，核对应用退出、程序/快捷方式/卸载项清理，合成用户文件与回收站内容保持完整。
5. 用另一个干净快照覆盖缺少WebView2的首次安装情形；分别记录安装运行时成功及不可用时的实际错误，不把联网安装成功外推为离线支持。

不使用真实用户目录或共享盘作为清理夹具，不在宿主运行安装/卸载。任何步骤受阻就记录该步骤和原因；未执行项不能标为通过。

## 当前验证边界

当前机器存在归简的既有HKCU安装记录，Windows Sandbox启动程序不可用，VirtualBox的唯一登记虚拟机不可访问。该检查没有提供可用的隔离Windows环境；本轮未执行安装、升级或卸载，未更改系统功能或修复虚拟机配置。
