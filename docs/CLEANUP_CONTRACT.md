# 清理与会话合同

## 1. 适用范围
Rust 命令、桌面 API 和 React 审阅状态之间的清理合同。清理不重新扫描目录。

## 2. 签名
`confirm_cleanup(target?: { groupId: string, path: string })`
返回 `{ report: CleanupReport, session: SessionView }`；前端将报告映射为数量摘要。

`cancel_cleanup()` 返回 bool；有活动清理时请求在当前文件完成后停止，无活动清理时返回 false。
事件 `cleanup-progress` 携带 `completedFiles`、`totalFiles`、`currentPath`（路径或 null）、
`movedCount`、`skippedCount`、`failedCount`。计数按已产生结果的文件计算。

`DesktopApi.subscribeCloseBlocked(listener: () => void): Promise<Unlisten>`
订阅 `operation-close-blocked`，无业务载荷；卸载页面时释放监听。

报告增加 `cancelled: bool` 和 `remainingFiles: number`；items 只包含实际处理项。
尚未开始的文件不伪装成失败或跳过，仍可在返回的会话中检查。

`keep_group(groupId: string)` 返回 `GroupSelection`，锁内一次清空目标组的
cleanupPaths 并将 reclaimableBytes 置零，其他组不变。已有操作、无会话或未知组
仍返回既有结构化错误，不用逐文件 IPC 模拟整组操作。

## 3. 请求与响应
不传 target 使用当前会话选择；传 target 临时构造单文件计划，不改其他选择。
执行前继续复核待清理文件与保留副本。对账只移除报告中成功回收的路径，
失败项保留；不足两份的组移出审阅列表。若原保留项被回收，按既有路径规则
保留一份幸存副本。对账完成才解除操作锁。
扫描数量与 issues 仍描述原扫描；返回会话不是再次扫描的结果。

结果页默认展示未处理项，并区分 failed、changed 和 blocked 的原因；已回收项
单独可查。返回审阅直接使用对账后的会话，保留人工选择，不自动执行重试。
容量表示已回收文件的估算容量；移入回收站并不意味着磁盘立即释放同等空间。

处理记录按完整报告筛选后分页，每页最多50项；统计不取当前页。筛选或新报告回到首页，范围缩短时调整有效页，不影响返回会话和路径动作。

前端 `getRecyclePathIssue(path: string): string | null` 只预告现有Shell长路径限制：先将扩展UNC前缀转普通UNC，或去掉扩展盘符前缀，再按UTF-16单元计数，达到260时提示。审阅、单项确认和批量确认使用同一函数；批量只计完整会话已选项，并说明原估算仍含受限文件。不自动取消选择或改变数量、容量；最终Rust路径校验、内容与身份复核仍是执行依据，前端无提示不代表可回收保证。

停止仅在文件之间生效，不中断当前文件的完整复核或 Windows 回收操作。
停止不回滚已完成项；已成功移入回收站的路径照常对账，剩余选择保留，随后解锁。
如果请求到达时全部文件已经处理完，cancelled 为 false，remainingFiles 为零。
前端等待实际清理响应后显示停止结果，不把发出请求等同于已经停止。

原生窗口 CloseRequested 以 Rust 活动操作为准：存在扫描或清理时 prevent_close，
发出 `operation-close-blocked` 无业务载荷事件；前端只用现有提示说明先停止后关闭，
不改会话、不自动取消、不自动退出。停止请求后至最终对账解锁前仍属于活动操作；
空闲关闭保持正常行为。

## 4. 校验与错误
| 条件 | 结果 |
| --- | --- |
| 已有扫描或清理 | Busy，不改选择 |
| 无扫描结果 | NoScanResult |
| 相对路径、跨组路径、未知组 | InvalidSelection / UnknownGroup |
| 内容或文件身份变化 | changed，跳过该项 |
| 无可验证保留副本 | blocked，不执行该项 |
| 回收失败 | failed，保留该项 |
| Shell 路径达到 260 个 UTF-16 单元 | 调用系统操作前拒绝，failed 并保留该项 |
| 当前项处理期间请求停止 | 完成本项后停止，不开始下一项，返回已完成报告 |
| 无活动清理时请求停止 | false，不改变会话或其他操作 |
| 扫描、清理或停止后尚未完成时关闭窗口 | 阻止关闭并发出提示事件，不自动停止 |
| 空闲时关闭窗口 | 正常退出 |
| 关闭提示订阅失败 | 显示提示不可用，Rust 关闭保护仍生效 |
| 清理命令整体拒绝，未收到可信报告 | 提示未能确认清理结果，保留具体错误；不推断零处理、不自动重试 |

## 5. 正常与异常案例
批量计划只处理已选路径。A 组全部保留后回收 B 组一项，A 组保持不变。
部分失败时已回收路径消失，失败项仍可审阅。扫描遗漏在空结果与非空结果中
均显示详情；“已检查范围内未发现重复”不表示遗漏目录已检查。

三项计划在第一项开始后请求停止：第一项完成报告与对账，后两项保留且
remainingFiles=2；不再调用它们的 TrashPort。开始前已请求停止时可返回零处理项。
最后一项处理完成后请求停止，不把正常完成显示为尚有剩余。
清理中关闭窗口应保留进程与最终报告；用户停止并收到结果后，可再次关闭窗口。
不能仅凭前端页面状态允许关闭，也不能把系统已接受关闭请求视为进程已经退出。
命令整体异常与报告中的逐项 failed 不同；前者可能发生在处理后，界面不能一概称为“未开始”。

单项入口收到可信失败报告时先采用返回会话并展示逐项原因。命令code为invalid_path、busy、unknown_group、invalid_selection或no_scan_result时属于明确前置拒绝；internal和未分类异常保守显示“未能确认清理结果”，保留实际错误并提示检查文件状态。未知结果弹窗不直接重提同一目标，只提供返回检查；关闭/新目标重置局部状态，不清空选择或自动重扫，pending结束后焦点落到可用关闭控件。前端分类不改变Rust执行授权或复核。

## 6. 回归验证
`command_state.rs` 验证选择隔离、原保留项回收、部分失败、Busy 与非法目标。
`desktopApi.test.ts` 验证请求字段和返回会话接续；`App.test.tsx` 验证无重扫、
未受影响组保留选择、失败会话和两类扫描诊断。测试使用合成文件和模拟回收端口。
停止回归须覆盖初始状态、当前项期间请求、正常结束、无活动清理、忙状态、
停止后再次清理，以及已成功/失败/尚未开始项的计数与会话接续。
链接安全合同须实际建立链接或重解析点执行隔离断言，不能因夹具权限不足而返回通过。
关闭保护回归覆盖扫描/清理开始、停止请求后仍忙、完成或放弃后空闲，及前端事件
与订阅失败；`scripts/native-smoke.mjs --close-during-cleanup` 在真实 WebView2 中
断言关闭被拦截、提示出现、清理报告返回、剩余文件完整，随后空闲关闭成功。
原生专项还须断言关闭助手退出码0、关闭请求被接受，以及应用退出码0；仅观察进程消失不足以证明正常关闭。

## 7. 禁止与正确做法
禁止：先覆盖整个会话选择，再回收单项并全目录重扫恢复默认建议。
正确：从权威会话派生局部计划，执行后原子对账，将报告与会话一起返回。

Windows Shell 必须设置 `FOF_NO_CONNECTED_ELEMENTS`，只处理批准的文件，
防止回收 HTML 时连带处理未选择的同名资源目录。保留 RECYCLEONDELETE 等
原有标志；不以性能优化为由取消每个文件执行前的完整摘要和身份复核。

真实 Windows Shell 使用 `cargo test --locked --test windows_shell -- --ignored --test-threads=1`
单独验证，覆盖普通回收、占用拒绝、HTML 资源隔离和长路径拒绝。只使用合成
临时文件并保留回收站内样本，不清空回收站；普通 cargo test 跳过这些测试。
长路径曾观察到源消失但无法验证回收站记录，故当前保守拒绝；不声称已证明
永久删除或支持长路径恢复。单元测试及模拟端口不能代替真实系统结果。
安装、硬件缩放和并发文件替换仍需单独验证；硬链接数变化可能保守要求重扫。
